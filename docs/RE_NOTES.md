# 大航海時代II 繁中 DOS 版 — 逆向分析筆記

本文件記錄已從原版檔案確認的格式和程式邏輯。每條結論都附有 MAIN.EXE 中的位置，方便複查。
位址記法：`seg0:xxxx` 指 MAIN.EXE 載入映像（檔頭 0x5200 之後）的線性偏移。

## 0. 程式概況
- MAIN.EXE：MZ，檔頭 0x5200，映像 277,569 bytes，重定位 5231 條，以 MS C 6 (1990) 編譯，大模式（far call）。
- DGROUP 段值 0x3815，對應映像線性 0x38150（入口 `seg0:3374`）。資料位址 `DS:xxxx` = 映像 `0x38150 + xxxx`。
- KOUKAI2.COM 是啟動器，依次執行 FMDRV.COM（FM 音源驅動）、OPEN.EXE（片頭）、MAIN.EXE、PW.EXE、END.EXE（結局）。它還掛上 int 65h 處理磁碟錯誤。
- 顯示：VGA 16 色平面模式（0x3C4/0x3CE 暫存器），每行 80 bytes（640 像素）。底層繪圖庫位於 seg0:0000–0x1000（組合語言）。

## 1. LS10 / LS11 壓縮（所有 *.LZW）
| 偏移 | 內容 |
|---|---|
| 0x000 | "LS10" 或 "LS11"，其後 12 bytes 為 0 |
| 0x010 | 256 bytes 字典 |
| 0x110 | 檔案表 `{u32be 壓縮長, u32be 原長, u32be 偏移}`，壓縮長為 0 時結束 |

解碼：位元流 MSB 優先。變長碼讀法：先數前導 1 的個數 n（遇 0 停止），再讀 n+1 位得 b，碼值 = b + 2^(n+1) − 2。
碼值 < 256 時輸出 `dict[碼值]`；否則距離 = 碼值 − 256，長度 = 下一個碼值 + 3，從輸出緩衝回拷。
壓縮長 = 原長時表示該項未壓縮。MAIN.EXE 中對應的 C 實作在 seg0:358d4 一帶（解到 0x2000 環形緩衝）。
實作：`tools/uw2lib.py: ls_unpack`。14 個 LZW 檔已全部解出，長度均與檔案表一致。

## 2. 調色盤
- 設定例程 seg0:159b `set_palette(start, count, ptr)`：每色 3 bytes，存放順序為 (B, R, G)，每值 4 bit；
  輸出到 DAC 的順序是 R=b1×4、G=b2×4、B=b0×4。單色設定例程 seg0:160a 使用 GRB 12bit 字。
- 映像中共有 11 組 16 色調色盤，前 8 色是固定的系統色（黑、藍、紅、粉、綠、青、膚、白）。
  另 8 色隨場景變化（晝、夜、黃昏等）。已輸出至 `assets/data/palettes.json`（含原始值）。
- 呼叫端如何選用哪一組調色盤，**待逆向**。

## 3. 字型
- `1.pat`、`2.pat` 由 MAIN.EXE 開啟（字串在 DS:a25c / DS:a269，檔案代碼存在 DS:bdae / DS:bdb0）。
- 字形 14×14，每字 28 bytes（每行 2 bytes）。每 18 字補齊一個 512 bytes 磁區：
  `offset(n) = (n−1)×28 + ((n−1) div 18)×8`（seg0:46e0）。
- 字碼轉字序在 seg0:4554（已完整移植到 `web/src/core/font.js: codeToGlyph`）：
  - 0x8130–0xAF68 取 1.pat；0xB030–0xD8C3 取 2.pat。
  - 尾碼索引 t：0x30–0x39 → 0–9；0x41–0x5A → 10–35；0x61–0x7A → 36–61；0x80–0xFD → 62–187（每個首碼 188 字）。
  - 首碼 0x81：n = t+1；首碼 0x82：尾碼 A0–F3，n = 尾碼 − 0xA0 + 0xEB；首碼 ≥ 0x92：n = (L−0x92)×188+591+t；首碼 0x83–0x90：n = (L−0x81)×188+591+t。
  - 2.pat：n = (L−0xB0)×188 + t + 1。無效碼返回 0x2228（超出字型檔範圍，畫面上是空白）。
- 半形 ASCII（< 0x200）：直接讀 BIOS ROM 8×8 字型 F000:FA6E（seg0:0b8c），每行重複兩次成 8×16（seg0:47ef）。
  `assets/font/rom8x8.png` 取自 DOSBox 內建的同一份 ROM 字型。
- 字序與 Unicode：1.pat 的 1–684 是符號區（Big5 A140–A3BF 加倚天擴充符號），685–6085 是 Big5 常用字，6086 是「碁」。
  2.pat 是 Big5 次常用字（去掉重複的兀、嗀）。光榮對少數字的位置做過調整，所以改用字形比對加分段 Viterbi 求解（`tools/build_charmap.py`）。
  **遊戲畫面一律用原版點陣字繪製**；Unicode 只用於 JSON 的可讀性，字碼表保證雙向唯一。全部文本經 Python 和 JS 兩端驗證，都能逐位元組還原。

## 4. 圖形格式
- 通用 PUT（seg0:02a7）：每 8 像素依序存 plane0..3 各 1 byte（byte 交錯）；旗標 0x8000 表示每行畫兩次。
- **KAO.LZW**：見第 11 節（第 0–127 項為具名人物頭像 64×80，第 128–255 項為發現物圖 48×48，檔尾另有 7 組頭像部件）。
- **PORTCHIP.LZW**：共 14 項，即 7 組 ×（30720 bytes 圖塊 + 4 bytes 參數）。每組 240 塊 16×16，4 planes「整塊依序」存放（先 plane0 共 32 bytes，再 plane1…）。
  港口載入流程見 seg0:88e9：依 `CHIP_NO.DAT[港口]` 選組，4 bytes 參數複製到 DS:bd78（用途待逆向）。
- **PORTMAP.LZW**：101 張 96×96 的圖塊索引（1 byte／格）。
- **WORLDMAP.LZW**：3 項，每項先有 1350 個 u16le 偏移，後接區塊資料（1350 = 45×30？與 WINDCUR.DAT 的 1350 bytes 吻合）。區塊編碼**待逆向**。

## 7. 顯示座標與 UI 系統（已完成，逐像素驗證）
### 7.1 畫面
- 模式 12h（640×480）。遊戲座標 640×400，畫到 VRAM 第 40 行起：`offset = (y+0x28)*80 + x`（seg0:0164、seg0:0780）。
  所以實際畫面上下各有 40 行黑邊。移植版畫布用 640×480，比例與原版顯示器相同。
- 繪圖庫座標：x 以 8 像素「欄」為單位（0..79），y 以像素為單位（0..399）。

### 7.2 文字主控台（seg0:49bd putc）
| DS 位址 | 意義 | 初值 |
|---|---|---|
| 8a1a / 8a1c | 游標 x 欄 / y 像素（夾限 0..79 / 0..400） | 0 / 0 |
| 8a1e | 行高 | 24 |
| 8a20 / 8a22 | 左 / 右邊界（欄） | 0 / 79 |
| 8a26 | 繪製模式（ESC M）：0 黑底、1 XOR、2 AND、3 OR、4 透明 | 0 |
| 8a27 | 前景色（ESC C，只接受 0..7） | 7 |
| 8a28 | 不透明背景色（ESC B，0 表示關閉，改用 8a26 模式） | 0 |

- 首碼 0x81–0xD8 先暫存，下一位元組組成雙位元組字。全形字 2 欄（14 行高），半形字 1 欄（ROM 8×8 每行重複兩次，16 行高）。
- 寫字前若 x 已超過 78（全形）或 79（半形）就先換行；寫完若 x > 右邊界再換行。
- 換行（seg0:4965）：若游標已在左邊界則**不動作**；否則 x=左邊界，且 y+行高 ≤ 400 時 y 才加行高。
- 控制碼：07 響聲（seg0:9646），08 退格，0A 換行，0D 回左邊界。
- 跳脫序列：`ESC = y x`（y=(c−0x20)×8，x=c−0x20）、`ESC C n`、`ESC B n`、`ESC M n`、`ESC F n`、`ESC R c`（左邊界=c−0x20）、`ESC W`（等待，seg0:59c1）。
  其他字元不會改變跳脫狀態（原版行為，已照搬）。
- 字形繪製：8a28≠0 時走 seg0:0653（逐平面合成不透明前景/背景色）；否則走 seg0:0572，依 8a26 選用 VGA 邏輯運算。

### 7.3 視窗（外框圖形 = DATA1.LZW 第 14 項，載入到緩衝 [0c86]）
- seg0:7358 `frame(x,y,w,style,h)`：四角 8×8 置於 2c20/2c40/2c60/2c80。邊框為 2ca0+style×0x80 的 8 行平鋪圖樣（上/左/右/下 = +00/+20/+40/+60，縱向相位 y&7），內部填色 7。
  畫完後文字區設為 x+1..x+w−2，游標 (x+1, y+8)，並輸出 `ESC C0 ESC B7`（黑字、底色 7）。有效 style 為 0、1、2。
- seg0:74f7 開視窗：先存背景（seg0:50c4）。若 [0ca4] bit0（環境設定「動畫效果」）開啟，就從中央向左右每步展開 1 欄，每步延遲 seg0:5998(1)，展開後**不重畫**；
  否則直接畫（seg0:773c）。兩種情況最後的文字區都是 x+2..x+w−3，游標 (x+2, y+16)。
- seg0:7779 帶陰影視窗：右側（x+w 欄，y+4 起）及下方兩條 2 行帶狀陰影，以 AND 模式套用 DS:8b4a/8b52/8b5a 的抖色圖樣。
- 視窗堆疊：緩衝 [0c88]（0xe40 段），堆疊頂 DS:0536；每層存 w×h×4 bytes 畫面資料 + 8 bytes {x,y,w,h}。
- seg0:796d 關視窗：若 h>16 且動畫開啟，就從上下兩端每次各還原 8 行，向中間收合（共 h/16+1 步）；否則一次還原。seg0:7a8e 為永不動畫的版本。

## 8. 輸入 / 計時 / 選單（已完成，差分驗證 41 項全部一致）
### 8.1 計時器
- 延遲經 INT 66h 由 FMDRV.COM 提供：`F1 01`（bx=倒數值）設定，`F1 00` 讀取。另有第二組 `F0 xx`。
- FMDRV 把 PIT 設為 4096 分頻（291.30 Hz）。每次 IRQ0 時累加器加 0x35，溢位就讓倒數減一，所以 **1 tick = 16.581 ms（60.309 Hz）**。原 BIOS 18.2 Hz 中斷以每 16 次轉送一次的方式保留。
- `seg0:5998(n)` 等 n tick；`59af(n)` = 6n tick（約 0.1 秒單位）；`59c1(n)` = 59af([0ca5]×n×2)（受「顯示速度」影響）；
  `59d7(n)` 等 n tick，但按 Enter/Esc/0 或滑鼠鍵會提前結束（其他鍵讀掉後繼續等）；`5a1b(n)` = 59d7(6n)。
- 視窗開關動畫每步 1 tick。

### 8.2 鍵盤 / 滑鼠
- `2aaf` kbhit（同時把 BIOS NumLock 強制打開）；`2ac9` 讀鍵（ASCII≠0 傳 ASCII，否則傳 0x100|掃描碼）。
- `3fc5` 轉為遊戲內碼：F1→16、F2→14、F3→02、F4→19、↑→1E、PgUp→3F、←→1D、→→1C、↓→1F、PgDn→3E、Del→7F，空白鍵→0D，其他功能鍵→FF。
- `4054` 讀一鍵後清空緩衝（防連發）；`3fae` 清空緩衝。
- 滑鼠：`4f75` 左鍵、`4fac` 右鍵、`507e` 任一鍵、`5092` 事件 = 0x80|左|右<<1；`4efa` 位置 = 驅動座標 +[8a92]（y 再 −40）。
- 游標由遊戲自己繪製（`31fd`）：24×24，先 AND 遮罩（圖形+0x48）再以顏色 15 OR 圖像。兩種外形：外框圖形 2570（箭頭）、2840（十字，熱點 +16）。
- `rand()`（`4d92`）：state = state×0x41C64E6D + 0x3039，回傳 (state>>16)&0x7FFF；`random(n)` = rand()%n。
  **選單每等待一次輸入就消耗一次 random(100)**，亂數序列會受玩家停頓時間影響，與原版相同。

### 8.3 選單引擎（0FEA 段，線性 0x131b2..0x1488f）
- 狀態：a14c 停用項目位元遮罩、a152 可否取消、a156 層級、a158 項數、a15e 行高、a160 游標、a162 框選高亮、bdcc 每項命中矩形 {x0,x1,y0,y1}。
- `142cd(C)` 選擇迴圈：C = 每列項目數（1 = 直式）。↑↓ 移動 C，←→ 移動 1（C=1 時不動），兩端循環。
  按 Enter 選到停用項目會被忽略；Esc 或 '0' 回傳 0xFF。按鍵碼 0x32/34/36/38（數字鍵）與方向鍵相同。
- 高亮：以外框圖形偏移 0 的全 FF 位圖，用 XOR 模式（顏色 7）反白命中矩形。停用項目用 0x280 的 AA55 點陣以透明模式覆蓋。
- 滑鼠：按下時持續追蹤命中項目並移動高亮，放開時若在項目上就等同 Enter；右鍵等同 Esc。可取消的選單在第一次按下時若點在視窗外，回傳 Esc。
- 入口：`14364` 帶陰影直式選單（行高 24，項目置中，關閉時還原）、`14411` 同上但保留、`144b9` 在現有視窗內、`14524` 自訂版面（呼叫端先填 bdcc）、
  `1458c` 在滑鼠位置彈出（第 1 層，行高 16）、`1469c` 是/否（第 2 層，GRAPH.DAT 第 0 張圖，回傳 1=是）、`147ab` 等待按鍵（文字游標下一行中央，以顏色 2 閃爍 0.4 秒亮 / 0.4 秒暗）。
- 選單資料：`2e09:57aa(idx)` 讀 MENU.DAT 第 idx 條：首 2 bytes = {寬, 項數}，接著是以 0 結尾的字串。

### 8.4 printf（`seg0:4194`，`4bad` 輸出到主控台）
- 格式 `%[-][0][寬][.精度][l](c|d|s|u|w)`，轉換字元不分大小寫；不認識的轉換字元原樣輸出。精度只對 %s 有效。負數的 '-' 在補齊字元之後。
- `%ld`/`%lu` 以「有號」比較判斷位數，所以 ≥2^31 的值只輸出一個字元（原版行為，已照搬）。
- `%w` 輸出全形數字（日文版遺留）。繁中版資料中沒有使用（掃到的 2 處都是二進位資料）。
- `2e09:56ee(n, ...)`：讀 MESSAGE.DAT 第 n 條（大端 16 位元偏移表），用 printf 輸出。

### 8.5 差分驗證項目

  內容涵蓋鍵盤、數字鍵、空白鍵、循環、停用項目、取消、滑鼠點選、右鍵取消、靠邊位置修正、保留游標。

### 9.2 編碼（seg0:0bcc..0fb7）
- 標頭：u16le 寬、u16le 高。16 色版本之後還有 8 個 u16le 圖樣表 T。
- 單位 = 4 像素 × 4 平面 = 16 位元圖樣：位元 0–3 平面 0（MSB 在左），4–7 平面 1，8–11 平面 2，12–15 平面 3。每行 160 單位。
- 繪製位置：單位索引 = x/4 + 160×y，所以 x 以 4 像素對齊。越界（w/h 為 0、超過 640/400）時傳回 −1，什麼都不畫。
- 命令（每行剩餘單位數 ≤ 本次數量時換行，最後一次可超出行寬）：
  - `1 0 dd nnnn`：同行回溯 dd+1 單位，複製 nnnn+1 個單位（逐單位、可重疊）。
  - `1 1 dd nnnn`：從上方 dd+1 行複製 nnnn+1 個單位。
  - 8 色版本 `0 nnn pppp` + 1 位元組：圖樣 = pppp<<8 | 位元組（平面 3 恆為 0），重複 nnn+1 次。
  - 16 色版本 `0 ssss nnn`：重複 nnn+1 次。ssss：0 = 全 0；1–6 = 取 1 位元組，依 6 種方式分配到平面
    （b / b高→平面2,b低→平面0 / b高→平面3,b低→平面0 / b<<4 / b高→平面3,b低→平面1 / b<<8）；7 = 取 2 位元組（大端）；8–15 = T[ssss&7]。
- 複製命令直接讀 VRAM 上的像素。原版這一點也照做：在畫面緩衝上原地解碼。理論上可以讀到圖像以外（左邊或上方）的像素，實際資料沒有這種情況。
- 解碼器在 VRAM 中以 VGA 資料旋轉暫存器（旋轉 4 位元）處理奇偶單位錯位的複製，語意上就是逐單位複製。

### 9.3 呼叫入口
- `seg0:5b5d(ax=x, dx=y, bx=n)`：16 色版本，取偏移表第 n 張。
- `seg0:5a91(ax=x, dx=y, bx=n)`：8 色版本，只接受 n=0（表中第 0 張）、2/4（固定偏移 0x1A67 = 第 2 張）、3/5（0x68B3 = 第 3 張）、0x3E（0x674F9 = 第 62 張），其他 n 不畫。
- GRAPH.DAT 中用 8 色格式的是第 0（是/否）、2、3（航海畫面框的 8 色版本）、62 張；其餘 61 張是 16 色格式。第 4、5 張是 2、3 的 16 色版本。
  呼叫端 `1dbdd` 等以 `sbb bx,bx / and bx,2 / add bx,3` 依旗標選 3 或 5。
- 調色盤不在圖像資料中，由各場景另外設定（待逆向）。

### 9.4 驗證
- GRAPH.DAT 65 張 × 16 色版本，各在 (0,0) 和 (4,3)（奇數單位起點）比對；8 色版本 6 個入口；越界不繪製 1 項。共 130 項，像素差異全部為 0。

## 11. 頭像（已完成，差分驗證 523 項一致）
### 11.1 KAO.LZW 結構
- 檔頭到 0x476A2 是 LS11 壓縮包，共 256 項：
  - #0–127：具名人物頭像，64×80（0x780 bytes）。`seg0:7cdd(ax=欄, dx=y, bx=編號)`。
